       fileSearch.setQueryFn([](const QString &q) {
           bool ok = false;
           const QVector<WinSearchQuery::FileResult> rows = WinSearchQuery::queryFiles(q, &ok);
           QVector<AppEntry> out;
           out.reserve(rows.size());
           for (const auto &r : rows) {
               AppEntry e;

               e.targetPath = r.path;      // full path — subtitle + launch + reveal (D-02)

           }
           return FileSearch::QueryResult{out, !ok};
       });

       fileSearch.setStatusFn([] {
           switch (WinSearchQuery::checkIndexStatus()) {
           case WinSearchQuery::IndexerState::Disabled:   return int(FileSearch::Disabled);
           case WinSearchQuery::IndexerState::Building:   return int(FileSearch::Building);
           case WinSearchQuery::IndexerState::Unavailable:return int(FileSearch::Unavailable);
           case WinSearchQuery::IndexerState::Ok:         return int(FileSearch::Ok);
           }
           return int(FileSearch::Unavailable);
       });
       fileSearch.setTrackedSource([&history] { return history.trackedExecutables(); }); // D-06/D-10

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-13 | S (spoofing) | Status-row copy integrity | mitigate | The three locked copies exist ONLY in FileSearch.cpp (04-02 single-home, grep-gated); QML renders `fileSearch.statusText` verbatim and can never invent copy. indexerOk gates visibility — the row is an overlay (never a model row, no focus, no keys — D-18 non-selectable), so it cannot be selected, launched, or keyboard-driven. |
| T-04-14 | I (injection) | addExecutable path flow | mitigate | Path originates in the NATIVE QFileDialog (no text-input surface), is stored via QSettings (04-03) and launched only via ShellExecuteEx open (user-triggered, D-12 snapshot) — never SQL, never a shell. Filter locked to `Executables (*.exe)`. ASVS L1: no injection surface. |
| T-04-15 | D (DoS/self) | Ctrl+Enter modifier regression | mitigate | launchFromKey branch order preserved: Ctrl+Shift (elevated) → Ctrl (reveal) → plain (normal). The Ctrl-only branch can only fire when Shift is absent — existing elevation and normal-launch paths are byte-identical (covered by tst_launch's unchanged suites + human step 4). Reveal is a no-op for Lnk/Uwp rows by design (04-03 policy), so Ctrl+Enter on an app row changes nothing. |
