## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| coordinator → model | Worker-thread file results cross into the UI-thread model via setFileResults (generation-stamped) |
| model rows → QML delegate | Rendered row content (paths, names, ranges) flows to the QML view |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | D (DoS/self) | setFileResults thread-affinity | mitigate | Documented contract: UI-thread-only delivery. FileSearch (04-02) guarantees it — the watcher completion runs on the UI thread; the worker lambda never touches the model (PATTERNS §2). Tests exercise direct UI-thread calls only. Model mutators are not thread-safe by design (single-threaded UI, existing QAbstractListModel discipline) — the boundary is enforced by construction, not locks. |
| T-04-11 | S (spoofing) | File row content (paths/names) from the index | accept | Same trust class as T-04-03 (04-01): rows describe the user's own local files; the model renders text and flags only — no execution, no parsing of payloads. Launching remains a separate user-triggered step (D-12 snapshot + 04-03 policy). No privilege boundary crossed. |
| T-04-12 | D (DoS/self) | File-row cap bypass | mitigate | kMaxFileRows enforced INSIDE mergeFiles after the union sort (D-03) — the cap is structural, not advisory: no code path can render more than 5 file rows per query (grep-gated constant, covered by fileCap5_D03). Apps are excluded from the drop loop (file-row positions only) — app visibility is provably unaffected. |
</threat_model>
