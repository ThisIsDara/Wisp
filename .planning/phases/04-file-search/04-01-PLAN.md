<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user query → OLE DB SQL | Unfiltered user keystrokes cross into a generated SQL statement |
| index rows → worker → coordinator | Rows from the user's own Windows Search index (file paths, names) enter the results pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | I (injection) | WinSearchQuery.cpp queryFiles | mitigate | SQL is generated ONLY by ISearchQueryHelper::GenerateSQLFromUserQuery (helper owns AQS escaping — RESEARCH §1, PITFALLS #5). Grep gate: no `+=`/append on the SQL buffer; the where-restriction is a compile-time constant string (buildWhereRestriction). ASVS L1: no parameter injection surface. |
| T-04-02 | D (DoS/self) | Worker COM apartment misuse | mitigate | CoInitializeEx(COINIT_MULTITHREADED) per batch with S_FALSE/RPC_E_CHANGED_MODE reuse discipline (AppCatalog precedent); all COM objects created AND released on the same worker thread; every HRESULT checked — failure returns empty rows, never a hang or crash (PITFALLS #3). |
| T-04-03 | S (spoofing) | Index row content | accept | Rows describe the user's own local files (path/name/isFolder only — no executable payload parsed). A malicious index row could only present a path; launching is a separate, user-triggered step (D-12 snapshot + LaunchController policy in 04-04). No privilege boundary crossed. |
</threat_model>
