### Auto-fixed Issues

**1. [Rule 1 - Bug] Visual Studio path fragment could never match its own fixture**
- **Found during:** task 2 (CurationRules implementation, GREEN gate)
- **Issue:** The plan specified path fragment `\visual studio`, but the measured fixture path is `C:\Program Files\Microsoft Visual Studio\2022\...` — the backslash precedes "microsoft" (space between "Microsoft" and "Visual"), so `\visual studio` never appears in the canonical install tree. tst_curation's `noiseBucketsHidden_CUR01` failed on the VS fixture.
- **Fix:** Changed the fragment to `\microsoft visual studio` with a comment explaining the measured path shape. Verified Pitfall-4 safety: VS Code's folder is "Microsoft VS Code" so it still does not match.
- **Files modified:** src/core/CurationRules.cpp
- **Verification:** tst_curation 7/7 slots pass via ctest
- **Committed in:** 5685b51 (task 2 commit)

**2. [Rule 3 - Blocking] Stale running wisp.exe locked the build output (LNK1168)**
- **Found during:** task 1 verification
- **Issue:** A leftover dev instance of `build/dev/wisp.exe` from an earlier session held the file open, so `.\build.ps1` failed with `LNK1168: cannot open wisp.exe for writing`.
- **Fix:** Killed the stale dev process (PID 77412) and reran the build — succeeded.
