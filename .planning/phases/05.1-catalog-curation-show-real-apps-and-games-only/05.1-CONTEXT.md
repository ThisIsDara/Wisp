# Phase 05.1: Catalog curation - show real apps and games only - Context

**Gathered:** 2026-08-11
**Status:** Ready for planning
**Source:** Session discussion (user request: "I have some issues with the filterings" → turned out to be a curation feature request)

<domain>
## Phase Boundary

The launcher's app catalog currently shows **everything** that lands in the Start Menu
(262 .lnk found on the user's machine). The user wants the default catalog to show only
**real apps and games they actually use** — a curated, clean list — while keeping an
escape hatch so anything missing can still be added. "There's no force for it to work on
everything."

This phase delivers catalog curation: a default-hidden rule set plus user-visible
controls to fix up the list (add missing entries, hide unwanted ones, persist both).

</domain>

<decisions>
## Implementation Decisions

### Scope / intent (locked)
- The catalog shown by default must contain only real apps and games — not every .lnk on the system.
- This is a *feature request*, not a bug: the existing behavior (show everything) is "working as intended", just wrong for the user's needs.
- The launcher must never silently drop an app that the user explicitly added — curation must be escapable.

### Measured reality (2026-08-11, user machine — the ground truth)
- 262 .lnk total across user + all-users Start Menu folders.
- ~60 real apps/games worth showing by default: Discord, Spotify, Steam, Telegram, Battle.net, Riot (VALORANT/TFT), CurseForge, WowUp, Mobalytics, OBS, Obsidian, Chrome, Edge, Word, VLC, 7-Zip, WinRAR, Ollama, LM Studio, Cursor, Trae, VS Code, Aseprite, Moonlight, Sunshine, VPN tools, TeamSpeak, Chatterino, Termius, ScreenToGif, CPU-Z, Core Temp, HWiNFO, ExitLag, games (Lies of P, Terraria, Torchlight 2, Oxygen Not Included, Machinarium, shapez 2…), plus UWP/Store apps.
- Noise buckets (~200 .lnk):
  - **Uninstallers (~25):** "Uninstall …" entries.
  - **Dev toolchains (~50):** MSYS2 ×5, Qt ×12, Python ×4, Git ×4, Node ×3, VS2022 ×6, Windows SDK ×10, CMake, Go, Java, OpenSSL.
  - **Windows system utils (~45):** Control Panel, Run, cmd, PowerShell ×4, Registry Editor, Event Viewer, Task Scheduler, services.msc, Disk Cleanup, ODBC, WSL, accessibility tools.
  - **Installer cruft (~80):** Inno Setup docs, "What is new in the latest version", Release Notes, License, Help, "Check For Updates", "Configure Java", driver tools.

### Curation mechanism (proposed direction — refine in planning)
- **Default-hidden rules:** name-pattern blocklist ("Uninstall…", toolchain markers) + skip hidden folders + UWP filtering policy.
- **Escape hatches (must exist):**
  - "Add executable…" row already exists from Phase 4 (persisted via `LaunchHistory::addExecutable` → `trackedExecutables()`).
  - New per-row "Hide" action (persisted) so users can prune anything the rules miss.
- Persistence must survive restarts (SettingsStore / registry precedent, D-13/D-14).

### OpenCode's Discretion
- Exact blocklist patterns and matching strategy (prefix vs word-boundary vs folder-relative).
- Whether hidden entries remain searchable but below a "show hidden" toggle, or are truly gone.
- Hide-persistence storage shape (settings key format).
- UWP curation policy (which Store apps count as "real").
- Whether file-search results get the same curation (user's complaint was about the app list; file search may be untouched in this phase).

</decisions>
