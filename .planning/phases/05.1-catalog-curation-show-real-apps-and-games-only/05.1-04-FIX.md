## Fix 1: Curated popular-app allowlist by default

### Root cause

`CurationRules::matches()` implemented a **blocklist** (hide noise buckets:
uninstallers, dev toolchains, system utils, installer cruft; show everything
else). The user's request was the opposite: *"too many unnecessary apps showed
up, I want around 200-300 handpicked"* — a curated **allowlist** of popular
apps (games, game launchers, messengers, famous apps) with everything else
hidden by default.

### What changed

- **`src/core/CurationRules.cpp`** — the four blocklist constant lists
  (`kNamePrefixes`, `kNameTokens`, `kSystemUtilNames`, `kSystemUtilExes`,
  `kPathFragments`) were replaced by a single `kCuratedNames` allowlist of
  ~280 well-known apps across: game launchers/stores (Steam, Epic Games
  Launcher, Battle.net, Riot Client, GOG Galaxy, Ubisoft Connect, EA app,
  CurseForge, Xbox, Playnite, itch.io, WowUp, Mobalytics, Rockstar Games),
  famous games (Lies of P, Terraria, Torchlight 2, Oxygen Not Included,
  Machinarium, shapez 2, Cyberpunk 2077, Elden Ring, Baldur's Gate 3,
  Minecraft, Stardew Valley, and a broad ~150-title catalog), messengers
  (Discord, Telegram, WhatsApp, Slack, Signal, Teams, Zoom, Skype), media
  (Spotify, VLC, MPC-HC, OBS Studio, Netflix, Plex, Kodi, editing suites),
  browsers (Chrome, Edge, Firefox, Opera GX, Brave, Vivaldi, Tor), productivity
  / dev tools (VS Code, Cursor, Trae, Obsidian, Notion, Office, Windows
  Terminal, 7-Zip, WinRAR, CPU-Z, HWiNFO, Core Temp, ScreenToGif, Termius,
  PuTTY, Ollama, LM Studio, Docker Desktop, Postman, Wireshark, JetBrains,
  Godot, Aseprite), VPN/network tools (NordVPN, ExpressVPN, ProtonVPN,
  Mullvad, Tailscale, WireGuard, …), gaming extras (TeamSpeak, Chatterino,
  Moonlight, Sunshine, ExitLag, Parsec, …), utilities/downloads, and
  well-known Store (UWP) apps (Microsoft Store, Netflix, Disney+, TikTok,
  Instagram, Adobe Express, …).
- **Matching semantics flipped:** `matches()` now returns `true` (hidden by
  default) when the entry is **NOT on the allowlist**. An entry is visible
  when its `displayName` **or** its `targetPath` basename (Lnk rows, no
  extension) contains an allowlist token at a word boundary, case-insensitive
  (existing `normalized`/`containsWord` machinery reused — punctuation like
  "7-Zip", "Battle.net", "cpu-z", "notepad++" normalizes cleanly). UWP/Store
  rows have no path → name-only matching. Source::File rows are still NEVER
  curated (CUR-04 escape hatch, belt-and-braces guard retained).
- **`src/core/CurationRules.h`** — header comment rewritten to document the
  allowlist semantics.
- **`tests/tst_curation.cpp`** — rewritten to allowlist fixtures:
  `allowlistedAppsVisible_CUR01` (reference apps + checkpoint list visible),
  `nonAllowlistedHidden_CUR01` (noise buckets + unknown apps hidden),
  `basenameMatch_CUR01` (display-name-vs-exe mismatch resolves via basename;
  word-boundary negative for "Battle.networx"), `uwpNameOnlyMatch_CUR01`,
  `fileRowsNeverCurated_CUR01`, plus the five unchanged CurationStore slots
  (persistence, last-action-wins, empty group, inert id, UWP aumid).
- **`tests/tst_catalog.cpp`** — only the fixtures that depended on blocklist
  outcomes were updated: `rebuildRemarkFromStore_CUR02` and
  `uninstalledHiddenIdInert_CUR02` now use allowlisted names ("Spotify"/"Steam")
  so their default-visible assertions hold under allowlist semantics. The
  precedence contract (shown beats hiddenIds, shown beats rules) is unchanged
  and re-verified.

### Semantics preserved (unchanged)

- `AppCatalog::markCurated` precedence: `shownIds` wins before rules,
  `hiddenIds` hides after rules.
- `CurationStore` last-action-wins: `hide()` clears the shown entry,
  `show()` clears the hidden entry — verified already correct, no store change
  needed.
- Hidden entries are never removed from the catalog snapshot (show-hidden /
  unhide need the row present).

## Fix 2: Hide must MARK, not remove — in-session unhide was impossible

### Root cause

`ResultsModel::hideSelected()` did `m_entries.removeIf(...)` — it **deleted**
the entry from `m_entries`. Consequences: `hiddenCount()` immediately read 0
in-session, so the "Show hidden (N)" footer (`visible: resultsModel.hiddenCount
> 0`) never rendered; and `unhideSelected()` had no row left to flip
(`hidden = false`) until a catalog rebuild re-marked rule-hidden entries.
The user's symptom: *"there's no option to unhide apps I hid. my list is kind
of empty after spamming Ctrl+H"*.

### What changed

- **`src/core/ResultsModel.cpp`** — `hideSelected()` now **marks** the matching
  `m_entries` row `hidden = true` instead of removing it. Visible-row
  disappearance is already handled by `buildAppOrder()`'s existing
  `hidden && !m_showHidden` skip. Query preservation discipline unchanged
  (no `setEntries`/full rebuild): mark → `buildAppOrder()` → `mergeFiles()`
  if query non-empty → clamp selection → emit `selectionChanged` only when the
  clamp moved. The `m_hideStore(id, true)` persistence call is unchanged.
- `unhideSelected()` already set `hidden = false` on the matching row — it now
  actually works in-session because the row still exists.
- **`src/core/ResultsModel.h`** — header comment updated (live marking, not
  live removal).
- **`tests/tst_model.cpp`** — `hidePreservesQuery_Pitfall3` strengthened to
  assert footer-countable `hiddenCount() == 1` after hiding; new slot
  `hideMarksNotRemoves_CUR02` locks the full cycle: hide → row gone from
  visible order but `hiddenCount() == 1` → show-hidden reveals the dimmed row
  (isHidden role) → in-session unhide restores it (`hiddenCount() == 0`) →
  default mode renders it again. All other hide/unhide slots reviewed and
  still valid under mark semantics.

### Grep gate

`m_entries.removeIf` no longer appears in `src/core/ResultsModel.cpp` (verified).

## User re-verification (7 steps)

1. Default catalog = curated allowlist only (~280 popular apps: games,
   launchers, messengers, media, browsers, dev tools, VPNs); noise buckets
   gone (no uninstallers, toolchains, system utils, installer cruft).
2. Ctrl+H hides the selected row; the "Show hidden (N)" footer appears with
   N > 0 (rule- AND user-hidden counted) — the Fix-2 in-session fix.
3. Clicking the footer toggles show-hidden mode; hidden rows render dimmed.
4. In show-hidden mode, select a dimmed row and Ctrl+H → it un-hides
   in-session (no restart, no catalog rebuild).
5. Persistence: hides and unhides survive restart (CurationStore INI).
6. "Add executable…" escape hatch untouched: File rows are never curated and
   never hideable (CUR-04).
7. No security regression: curation is UX visibility only, not access control.
