## Decisions Made
- **Allowlist over blocklist (user-directed):** the default list is now a curated set of ~280 well-known apps/games; everything else defaults hidden. User hide/show overrides always win over the allowlist (shownIds/hiddenIds consulted before matches()).
- **Hide marks in place** — removal made unhide impossible; the visibility branch does the filtering (05.1-03's per-site skip already handles both).
- **hiddenCount must be a property** — QML bindings never re-evaluate on method calls; NOTIFY is mandatory.
- **Menu = shell-owned in-window overlay** — never a Popup window on these scale-transformed delegates.

## Deviations from Plan

### Auto-fixed Issues

**1. [Bug - checkpoint] hideSelected removed entries → unhide impossible**
- **Found during:** checkpoint pass 1 ("no option to unhide apps I hid")
- **Issue:** the model removed the entry outright; unhide had no target.
- **Fix:** mark `hidden=true` in place; visibility branch excludes it. (`de9bf14`)
- **Verification:** unhide via Ctrl+H and footer both restore the row; persistence round-trip green.

**2. [Bug - checkpoint] hiddenCount as Q_INVOKABLE method → footer never rendered**
- **Found during:** checkpoint pass 2 ("nothing above Add executable")
- **Issue:** `Q_INVOKABLE int hiddenCount()` — QML `resultsModel.hiddenCount > 0` compared the function object to 0, always false.
- **Fix:** promoted to `Q_PROPERTY` with `hiddenCountChanged` NOTIFY emitted at every mutation site (setEntries, hideSelected, unhideSelected). (`5cfaf80`)
- **Verification:** footer appears with N>0; count updates live on hide/unhide.

**3. [Design - user-requested] right-click context menu — three robustness iterations**
- **Found during:** checkpoint pass 3 ("add a right click menu")
- **Issue chain:** QQC `Menu` rendered default-sized/ugly and ignored style overrides → hand-rolled Popup opened off-position on the scale-transformed delegates ("nothing shows up") → in-window overlay finally deterministic.
- **Fix:** delegate signal (`contextMenuRequested(index, isHidden, x, y)`, coords via `mapToItem(row.ListView.view, …)`) → MainWindow-owned `ctxMenu` overlay (z-sibling of the list), clamped to shell edges, closed by dismissal catcher / Escape / launch. (`0276746`)
- **Verification:** user-approved; full suite green.

## Issues Encountered
- **QML binding semantics (Qt 6.11):** bindings to `Q_INVOKABLE` methods are evaluated once — state that must drive QML `visible:`/`text:` needs `Q_PROPERTY` + NOTIFY. (Found via user report, fixed in `5cfaf80`.)
- **Popup windows vs. transformed delegates:** a `Popup` parented to a scale-transformed delegate (`scale: 1.04`, `transformOrigin: Item.Left`) opens off-position — and a QQC `Menu` resists compact styling. The codebase's own convention (concrete widgets, no QQC) pointed to the overlay solution.
- **GUI app console output:** `console.log`/stderr from a running wisp.exe is not reliably visible — instrumented debugging was inconclusive; behavioral testing with the user was the effective loop.
