## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] setEntries' initial order loop missed the hidden skip**
- **Found during:** task 2 GREEN gate (showHiddenToggleReveals_CUR03 failing: rowCount 3, expected 1)
- **Issue:** The plan specified the visibility skip in buildAppOrder's TWO loops, but there is a third order-building site: setEntries' own initial alphabetical loop (ResultsModel.cpp:40-44). The default state (fresh catalog + empty query) never reaches buildAppOrder — `setQuery(QString())` early-returns because m_query starts empty — so hidden rows rendered in the default list, violating must-have truth #1 ("hidden rows are excluded from results by default") exactly as the plan's own test asserts.
- **Fix:** Added the same `hidden && !m_showHidden` skip to the setEntries loop with a comment documenting why this third site must apply the identical branch; m_ranges sized to m_order.size() so the roles stay aligned after the skip (previously sized to m_entries.size(), which only coincidentally matched).
- **Files modified:** src/core/ResultsModel.cpp
- **Verification:** showHiddenToggleReveals_CUR03 green; tst_model 28/28; full ctest 17/17 (all pre-existing slots unchanged — no fixture has hidden entries, so the default loop behavior for them is identical)
- **Committed in:** 669f765 (task 2 commit)
