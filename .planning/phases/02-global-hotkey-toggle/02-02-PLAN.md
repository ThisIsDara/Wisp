    - **Show path (`void show()` / `bool canShow()` / `void showUserRequested()`):**
      - `bool canShow() const` — false if fullscreen guard active: injectable `std::function<WinFullscreenGuard::State()> fullscreenGuard` (default = &WinFullscreenGuard::currentState; tests inject a fake).       - `void showUserRequested()` — **explicit user intent** ("Open wisp" tray item, 02-03; D-02.3): shows regardless of the fullscreen guard — same show→raise→deferred-requestActivate sequence, but skips `canShow()`. The guard protects only passive hotkey summons; a deliberate tray click always shows. (Contract: signature `void showUserRequested()` — declared and implemented in THIS task; 02-03 only wires TrayIcon::openWisp to it.)
    - `void hideAnimated()` — if visible:  QMetaObject::invokeMethod on the QML window's JS function `dismiss()` (existing, plays close animation). Falls back to win->hide() if invoke fails.
    - `void hideNow()` — **instant, no animation** — `win->hide()` (HOTK-03 launch dismiss; the API Phase 3 calls).
    - `void toggle()` — state switch: Hidden → try show() (guard-checked); Visible → hideAnimated(). Exposes `toggled()` signal? Not needed — tests use state().

If active becomes true again before timeout → stop timer (m_grace->stop()).

    All interactions with the window go through QPointer<QQuickWindow> (guard against dangling). All policy must be C++-testable: guard injectable, timer visible, no QML dependencies.

    Wire QTimer: m_graceTimer = new QTimer(this); setSingleShot(true); connect timeout.
    Include <QtQml/QQmlEngine> only if needed — prefer QMetaObject::invokeMethod on the QQuickWindow QObject (we pass the window as QObject* param typed QQuickWindow*; invokeMethod("dismiss") resolves QML-declared JS functions on the root QML object).
