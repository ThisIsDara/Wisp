## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → Settings section | Root paths enter via the native folder picker only; interval values via ± buttons — no free-text input, no wildcard/path-pattern parsing |
| SettingsStore → ScanService | Store is UI-thread-only (no mutex); the scan worker must never touch it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | DoS | SettingsWindow::addScanRoot | mitigate | Roots are directories only (native picker — no wildcards, no file patterns, D-05); duplicate roots are rejected before persist; interval clamped 1..1440 at BOTH the store and the service consumption sites; scans stay on the dedicated low-priority pool (07-03) regardless of root count |
| T-07-03 | Tampering | SettingsStore::setScanRoots | mitigate | Every stored root passes `QDir::toNativeSeparators` once at write (Pitfall 5) and is read back verbatim — the snapshot lambda in main.cpp (07-04) forwards the same normalized form to walkAndDelta, so memo keys and dedupe keys agree across every path producer |
| T-07-02 | Tampering | SettingsStore scan keys | mitigate | INI values are typed (QStringList / int with qBound) and silently default on garbage (`scanRoots` → empty = D-04 NoRoots; `scanIntervalMinutes` → 10) — a tampered INI degrades to safe defaults, never a crash; index file corruption is separately guarded in 07-01 |
</threat_model>
