```cpp
class ScanService : public QObject {
    Q_OBJECT
    Q_PROPERTY(QString lastScanSummary READ lastScanSummary NOTIFY scanStateChanged)
public:
    enum ScanState { Idle = 0, NoRoots, Scanning, Error };  // ordinals → FileSearchState via main.cpp explicit map
    struct ScanSettings { QStringList roots; int intervalMinutes = 10; };
    using ListFn = std::function<WinDirListing(const QString &path)>;
    using SettingsSource = std::function<ScanSettings()>;
    explicit ScanService(QObject *parent = nullptr);
    void setListFn(ListFn fn);
    void setSettingsSource(SettingsSource fn);
    void setIndex(FileIndex *index);
    void setPool(QThreadPool *pool);   // dedicated pool; nullptr → global (tests inject)
    void start();                       // boot: snapshot; arm timer if roots; NO scan
    void requestScan();                 // "Scan now" / roots-changed funnel — single-flight + coalesce
    void refreshInterval();             // re-arm timer from a fresh snapshot
    int stateOrdinal() const;
    QString lastScanSummary() const;    // "" when never scanned
signals:
    void scanStateChanged();            // emitted only when state or summary actually changed
};
```

       const auto worker = [s, listFn, index]() -> FileIndex::WalkOutcome {

           try {
               return index->walkAndDelta(s.roots, listFn);   // const, read-locked

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → filesystem | The scan worker (dedicated pool) calls walkAndDelta → ListFn against user-selected roots; a huge/deep/looping tree must not stall the UI or the typing path |
| SettingsStore → ScanService | Roots/interval are UI-thread state; the worker must never read the store (no mutex there — SettingsStore.h:14-18) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | DoS | ScanService::dispatch worker | mitigate | Dedicated pool (`m_pool` — production main.cpp creates a 1-thread pool; never the global pool), job body drops its own priority (`QThread::LowPriority`), single-flight + coalesce bounds concurrency to one scan + at most one follow-up; FileIndex reads are read-locked (apply blocks at most the lock hold time); queryCandidates cap (07-01) bounds per-keystroke work; test `singleFlightCoalescesConcurrentScans` proves the gate |
| T-07-04 | DoS | ScanService::onScanFinished | mitigate | apply + save on the UI thread are bounded (delta + ~10ms QSaveFile write); failed/looping listings degrade to Error state via `failedListings` — never a hang (worker catches everything, belt-and-braces catch in onScanFinished) |
| T-07-03 | Tampering | ScanService settings snapshot | mitigate | Roots/interval flow through ONE `SettingsSource` lambda invoked on the UI thread at dispatch; the worker receives a by-value copy — no store reach-in possible by construction (grep gate + `snapshotReadOnUiThread_Pitfall4` test) |
