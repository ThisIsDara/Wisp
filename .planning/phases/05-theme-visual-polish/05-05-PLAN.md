<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| QML → model/provider | displayName/matchRanges/iconKey flow into rich-text HTML built in the delegate — model content originates in .lnk names, file paths, and package metadata (user/OS-writable sources). |
| QML → SettingsStore | accent value from wisp.ini flows to Theme.accent; QML text rendering consumes it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-18 | Tampering | Rich-text HTML injection via displayName (e.g., a .lnk named "x<img onerror=...>") | mitigate | Qt rich text is a restricted subset (no script/event handlers; verified Qt 6.11 table — RESEARCH Pattern 3). Additionally build the HTML via Qt-escaping of displayName segments (Qt.escape() or replace &,<,> before wrapping in spans) — exact escape in the delegate's buildTitleHtml. |
| T-05-19 | Tampering | Icon id from QML into provider | mitigate | iconKey passes through encodeURIComponent and is decoded by the provider before parseKey (05-01 rules); invalid → null → monogram. No path/command execution (05-04 threat model). |
| T-05-20 | DoS | Crossfade/animation cost on many rows | mitigate | ~8 visible rows (640×400 shell); 120ms single opacity behavior; icons already LRU-cached (05-02). No unbounded animation count. |
| T-05-21 | Tampering | wisp.ini accent value (e.g., malformed color string) | mitigate | SettingsStore (05-03) silently falls back to #0078D4 on any parse failure (D-16); QML never parses the INI directly. |
</threat_model>
