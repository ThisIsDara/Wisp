# Phase 5 — UI Design Contract (Theme & Visual Polish)

> Visual and interaction contract for the launcher **polish pass**: sleek dark theme, accent-colored selection + match highlighting, async icons, styled scrollbar + empty state. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Qt adaptation note:** this is a Qt6/QML desktop app, not web. Tokens are logical pixels (Qt PMv2 handles DPI), typography is Segoe UI Variable (Windows-native), colors are hex, the component library is project-authored QML, Registry Safety is N/A (no component registries in Qt). This contract **extends** the Phase 1 baseline (01-UI-SPEC.md) — geometry, core colors, typography, and animation contracts from Phase 1 remain locked and are restated only where they change.
>
> **Source of truth:** all decisions below trace to 05-CONTEXT.md (D-01..D-16, locked), 05-RESEARCH.md (verified Qt 6.11.1 / MS API facts), and the existing `qml/Theme.qml` token singleton. Zero literal values may enter QML — every new color/spacing/duration ships as a Theme.qml token first (01-UI-SPEC token-only rule).

## Typography

Locked from Phase 1 — **unchanged sizes, weights, and line heights**. Family: `Segoe UI Variable` → `Segoe UI`. Exactly two weights: regular (400), semibold (600).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Query | 18px | 400 | 1.2 | Search field text |
| Title | 15px | 400 | 1.2 | Result titles — **the only line that carries match highlighting (D-08)** |
| Subtitle | 12px | 400 | 1.2 | Metadata line (path / package name) — **never highlighted (D-08)** |
| Keycap | 12px | 600 | 1.2 | Keyboard-hint labels |

**Phase 5 typography rules:**
1. Match runs render via **color + background chip only** — never weight or size change (no re-measure, no layout shift; selection weight rule from Phase 1 stays 400 on the title).
2. Rich text disables `Text.elide` (verified Qt 6.11.1) — the title Text must be elided **manually** via `FontMetrics.elidedText(model.displayName, Qt.ElideRight, titleWidth)`; the FontMetrics font must mirror the title Text's font exactly (research Pitfall 6).
3. Selected-row remap (D-06): matched runs become **white on accentDark chip**; the rest of the title is white `textPrimary`. Unselected: matched runs `accentLight` on an accent-tinted chip; non-matched text `textPrimary`.
4. Empty-state glyph renders at 16px in Segoe MDL2 Assets (declared: fontSizeSubtitle × 4/3 = 16px), color `textSecondary`.

## Color

Phase 1 60/30/10 split over the launcher surface stays; the **accent system becomes settings-backed and runtime-derived** (D-13..D-16).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1E1E1E` (surface, unchanged) | Window surface, row base |
| Secondary (30%) | `#2D2D30` (surfaceSecondary, unchanged) | Hover row bg, monogram slot, inset wells |
| Border | `#3F3F46` (unchanged) | 1px hairline, **scrollbar thumb** (new usage) |
| Accent (10%) | **`#0078D4` default — now mutable, read from SettingsStore at startup** (D-13/D-16) | See reserved-for list below |
| Accent light | **derived** `Qt.lighter(accent, ~1.45)` — targets ≈ `#58A6FF` at default (A5, tune at visual check) | Match-highlight text, selection bar, folder ▸ glyph |
| Accent dark | **derived** `Qt.darker(accent, ~1.4)` — ≈ `#005896` at default | Selected-row highlight chip bg (D-06) |
| Text primary | `#F5F5F5` (unchanged) | Titles, selected-row title text |
| Text secondary | `#A0A0A0` (unchanged) | Subtitles, placeholder, empty state, hovered scrollbar thumb |
| Destructive | none | No destructive actions in this phase |

**New tokens (D-10 full token set):**

| Token | Value | Usage |
|-------|-------|-------|
| hoverBg | `#2D2D30` (dedicated token; same value as surfaceSecondary) | Hover row background (replaces inline surfaceSecondary in ResultsRow) |
| pressedBg | `Qt.darker(surfaceSecondary, 1.15)` ≈ `#26262A` (derived, no literal) | Pressed row / action background (transient, sub-100ms) |
| placeholderColor | `#A0A0A0` (dedicated token; same value as textSecondary) | Search field placeholder (replaces inline usage) |
| chipTextUnselected | accentLight (derived) | Matched-run text, unselected row |
| chipBgUnselected | accent at ~20% alpha blended over surface → opaque | Chip behind matched runs, unselected row |
| chipTextSelected | `#F5F5F5` (textPrimary) | Matched-run text, selected row (D-06) |
| chipBgSelected | accentDark (derived) | Chip behind matched runs, selected row (D-06) |
| scrollbarThumb | `#3F3F46` (border) | Overlay scrollbar thumb (rest state) |
| scrollbarThumbHover | `#A0A0A0` (textSecondary) | Thumb while hovering the list |
| scrollbarTrack | transparent | Overlay scrollbar — no track, no layout space |
| emptyStateGlyphColor | `#A0A0A0` (textSecondary) | Empty-state glyph (D-11) |

**Accent reserved for EXACTLY** (unchanged from Phase 1 + Phase 5 additions): selected-row highlight background, selection left bar (accentLight, 8px), match-highlight text + chips (accentLight/accentDark), focused search-field caret + selection, folder ▸ glyph, and the "Add executable…" hover complement. It is **not** for: buttons, borders, bulk fills, hover backgrounds (hover stays `#2D2D30`), or the empty state (muted `textSecondary`).

**Derivation contract (D-15):**
- `Theme.accent` becomes the **single mutable color source**; `accentLight` and `accentDark` are `readonly` bindings derived from it (e.g. `Qt.lighter(accent, 1.45)` / `Qt.darker(accent, 1.4)`). No hand-picked shade constants (research anti-pattern).
- The rename ripple is minimal: `Theme.accent` loses `readonly`; every existing consumer already binds to it.
- **Contrast guards:** derived accentLight on the dark surface must hold ≥ 4.5:1, and white (`textPrimary`) on accentDark must hold ≥ 4.5:1. If a Phase-6 picked accent would violate either, clamp the derived factor in Theme.qml (planner's call within D-15; verify with 3-4 probe accents during the visual pass).
- **Silent fallback (D-16):** missing/corrupt setting → `#0078D4`, no toast, no tray notification.
- Belt-and-suspenders for binding re-evaluation (A7): the MainWindow `Connections` handler that writes `Theme.accent` may also assign the derived variants if visual verification shows stale shades — the bindings are primary, not the assignments.

## Animation & Motion Contract

Phase 1 open/close contract (150ms OutCubic open / 140ms InCubic close, opacity + Scale only) is **unchanged and untouched**. Phase 5 adds only micro-animations that never touch the animated subtree:

| Property | Duration | Easing | Notes |
|----------|----------|--------|-------|
| Icon crossfade (D-04) | **120ms** | Linear (opacity only) | Monogram → real icon on `Image.Ready`; warm cache = instant, no flash (`Component.onCompleted` status check) |
| Scrollbar overlay fade (D-12) | **120ms** | Linear (opacity only) | Fade in/out on `active`/`hovered` |

**Token:** `animFade: 120` in Theme.qml (both uses share the token; planner may split if needed — values are locked).

Hard rules:
1. **No animation on selection/highlight** (D-09: selection treatment is final form, no entrance animation; D-07 chips appear statically with the row).
2. **No per-frame work:** chip geometry + HTML rebuild only on width change, model row data change, or `isCurrentItem` change (research Pattern 3 / anti-pattern "HTML on every frame").
3. Icon crossfade animates **opacity only** — never width/height/source switching mid-frame.
4. Scrollbar uses opacity fade only; `policy: AsNeeded`; visible while `active` (scrolling) or `hovered` (list hover), per verified Qt 6.11 props (research Pattern 5).

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Icon load (D-02/D-04) | `Image { source: "image://wispicons/" + encodeURIComponent(model.iconKey); sourceSize: Qt.size(32,32); cache: false; asynchronous: true }`. Monogram visible until `Image.Ready` → 120ms crossfade. Failure (null QImage) → monogram persists **silently** (D-16 discipline; failures are not cached — re-extract on demand, research Pattern 1). `cache: false` is mandatory — QPixmapCache double-caching would unboundedly defeat the LRU (research Pitfall 2) |
| Match highlight (LAUN-06, D-05..D-08) | Title line only; matched runs = accentLight text + rounded chip (unselected) / white text + accentDark chip (selected). Chips metric-positioned via `FontMetrics.advanceWidth` under the rich-text spans; runs clamped at the manual-elide boundary; rebuilt on width/data/selection change. Subtitle never highlighted. Fallback (documented, last resort): rich-text rectangular `background-color` spans if metric misalignment shows (research Pattern 3) |
| Selection (D-09) | **Unchanged final form:** accent bg + 8px accentLight left bar, current row only. Hover = `hoverBg`, never accent. This phase tunes tokens only (pressedBg added), no rework |
| Hover / pressed | Hover row bg `hoverBg`; pressed (mouse-down) row/action bg `pressedBg` — transient, sub-100ms, no animation |
| Scrollbar (D-12) | Auto-hide overlay: `ScrollBar.vertical` attached to the results ListView, `policy: AsNeeded`, `visible: active || hovered`, 120ms opacity fade. Thumb 6px wide, 3px radius, `#3F3F46`; hovered thumb `#A0A0A0`; no track |
| Empty state (D-11) | Centered column: 16px Segoe MDL2 glyph (U+E721) + existing message copy, all `textSecondary`. Existing gating preserved (`resultsView.count === 0 && fileSearch.indexerOk`); indexer status row and empty state remain mutually exclusive |
| Accent wiring (D-13..D-16) | Accent read once at startup from SettingsStore (default `#0078D4`, silent fallback); `Theme.accent` written via MainWindow `Component.onCompleted` + `Connections` on `accentChanged` (research Pattern 4 — never a singleton↔context-property read, never `qmlRegisterSingletonInstance`). No visual accent change mid-session this phase; the reactive path exists for Phase 6's picker |
| Keyboard / launch | **Untouched** — all Phase 3/4 keyboard, hover-arbitration, and launch contracts carry over verbatim |

## Data Contract (iconKey — the only model change)

`ResultsModel` gains an `iconKey` role (string) that yields the provider id per source (research Pattern 2):

| Source | iconKey shape | Derivation |
|--------|---------------|------------|
| Lnk | `iconPath;index` | iconRef passthrough (existing field, format already produced); empty iconRef → `path:` + targetPath |
| Uwp | `uwp:<PackageFullName>\|<appId>` | aumid split after the last `!`; carries manifest identity without per-request enumeration |
| File / folder | `path:` + targetPath | plain shell path — `IShellItemImageFactory` works on any shell item |

Provider contract:
- Registered as **"wispicons"** → `image://wispicons/{key}` (D-02: provider-based channel; exact scheme per RESEARCH, engine takes ownership, registered BEFORE `loadFromModule`).
- `requestImage` runs on the engine's dedicated provider thread — blocking extraction is architecturally safe (verified Qt 6.11 contract; UI thread never waits).
- Extract at **64px fixed** (crisp at 200% dpr), downscale to `requestedSize`; cache 64px QImages in a bounded LRU (**~500 entries ≈ 8 MB**, inside D-03's 5-10 MB budget); LRU under QMutex, reentrant (research Pattern 1).
- Classic: `SHCreateItemFromParsingName` → `IShellItemImageFactory::GetImage({64,64}, SIIGBF_ICONONLY|SIIGBF_RESIZETOFIT|SIIGBF_SCALEUP)`; index>0 → `ExtractIconExW`; `QImage::fromHBITMAP(...).copy()` before `DeleteObject` (A1-safe).
- UWP: manifest `Square44x44Logo` via `InstalledLocation`, `SHLoadIndirectString` for `ms-resource:` URIs, scale-variant probe {400..100} nearest to dpr, `GetLogo({64,64})` stream fallback; try/catch everything (WinUwpEnumerator batch discipline).
- Failure → null QImage (silent monogram), never cached. Encoding: `encodeURIComponent` in QML + defensive last-`;` split in the provider (research Pitfall 4 — 1-minute spike locks the round-trip).
