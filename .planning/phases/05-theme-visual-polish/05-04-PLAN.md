<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted .lnk content → provider | iconKey strings originate in Start Menu .lnk files (user-writable). They flow through QML encodeURIComponent → provider → parseKey → seams. |
| provider thread → extraction seams | IconProvider calls WinIconExtractor/WinUwpLogo on Qt's provider thread (05-01 threat model applies). |
| UWP package store files → WinRT seam | AppxManifest parsed in 05-01's seam; this plan only routes ids to it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-14 | Spoofing | iconKey → requestImage id | mitigate | parseKey (05-01) has exact prefix rules and is unit-tested; malformed/foreign ids → invalid → null QImage → monogram. Provider never interprets ids as shell verbs or paths to execute — extraction only (05-01 T-05-01). |
| T-05-15 | DoS | Unbounded provider requests (fast typing re-requests rows) | mitigate | LRU capped ~500/~8MB (05-02 D-03); Image { cache: false } forces provider round-trips but the LRU absorbs repeats; failed extracts are not cached so re-requests re-extract (sub-10ms, accepted). |
| T-05-16 | Elevation | addImageProvider registration | accept | Provider registered once in main.cpp before loadFromModule; no user input influences which provider serves the scheme. |
| T-05-17 | Information disclosure | UWP iconRef leaks PFN/appId into model | accept | PFN/appId are public package identifiers (already displayed in Start Menu app metadata); no secrets involved. |
</threat_model>
